# 蜜蜂虚拟飞行仿真系统软著材料与演示方案（Worker-2 草案）

## 1. 文档定位
本文档用于把当前 Unity 项目整理成适合软件著作权申报、演示答辩和截图取证的材料草案。原则如下：

1. **能演示**：每项功能都能在 `Assets/Scenes/Demo.unity` 中直接操作或观察。
2. **能截图**：每项功能都能形成稳定的 UI、轨迹、姿态、目标行为或参数化界面截图。
3. **能写成模块**：每项功能都能落到独立脚本或明确脚本职责，便于软著说明书拆分模块。
4. **不过度复杂**：不引入复杂插件，不做大型重构，不夸大为真实生物实验系统。

## 2. 当前项目结构与脚本现状（只读分析）

### 2.1 主要场景与资源
- 演示场景：`Assets/Scenes/Demo.unity`
- 蜜蜂预制体：`Assets/Resources/Bee.prefab`
- 主要脚本目录：`Assets/Scripts/beeljk`

### 2.2 当前脚本职责梳理

| 脚本 | 当前职责 | 软著可描述模块 |
|---|---|---|
| `BeeSimulation.cs` | 手动/自动飞行控制、振翅扰动、障碍规避、地面规避、姿态变化、噪声扰动 | 飞行控制模块、扰动模拟模块、避障控制模块、姿态控制模块 |
| `BeeTargetController.cs` | 目标搜索、趋近、悬停、采集、玩家采集触发 | 目标行为模块、采集行为模块 |
| `BeeSimulationManager.cs` | 轨迹记录与 LineRenderer 轨迹绘制 | 飞行轨迹可视化模块 |
| `VisualizationManager.cs` | 调试射线/受力/轨迹的统一开关与按钮控制 | 可视化开关模块、交互展示模块 |
| `CameraFollow.cs` | 相机跟随、观察偏移、边界限制 | 演示相机模块 |
| `CurlNoiseField.cs` | Curl Noise 扰动场计算 | 振翅扰动/环境扰动参数模块 |
| `GameManger.cs`（类名 `SimplePauseManager`） | 暂停/恢复 | 演示控制模块 |

### 2.3 Demo 场景已确认的绑定关系
- `Demo.unity` 中的 **Bee** 对象挂载：`BeeSimulation`、`BeeTargetController`
- `Main Camera` 挂载：`CameraFollow`，跟随目标指向 Bee
- `Main` 对象挂载：`BeeSimulationManager`
- `VisualizationManager` 对象挂载：`VisualizationManager`
- `GameManger` 对象挂载：`SimplePauseManager`
- Bee 的 `BeeTargetController.targets` 在 Demo 场景中已绑定 3 个目标点（名称为 `fengchao`、`fengchao (1)`、`fengchao (2)`）

### 2.4 当前项目已经具备、且适合软著展示的功能
1. **蜜蜂飞行轨迹可视化**：`BeeSimulationManager.cs`
2. **振翅扰动模拟**：`BeeSimulation.cs` + `CurlNoiseField.cs`
3. **目标趋近与采集行为**：`BeeTargetController.cs`
4. **障碍规避**：`BeeSimulation.cs`
5. **姿态变化**：`BeeSimulation.cs` 中已有侧倾/俯仰相关参数
6. **参数化控制**：多个脚本暴露 Inspector 参数，可直接截图
7. **演示与交互功能**：`VisualizationManager.cs`、`CameraFollow.cs`、`SimplePauseManager`

### 2.5 当前项目不足（软著视角）
1. 缺少**面向演示的状态 UI**，例如速度、高度、模式、目标距离、采集状态。
2. 缺少**采集数量统计**，不利于把“采集行为”写成完整业务流程。
3. 缺少**自动/手动/演示模式的一键切换入口**，答辩时操作成本偏高。
4. 轨迹显示已存在，但缺少**更明确的演示开关、清空、重点截图说明**。
5. 扰动参数虽存在，但缺少**面向非技术评审的可视化说明**。
6. `GameManger.cs` 文件名与类名 `SimplePauseManager` 不一致，文档描述时不够规整。
7. 当前 README 说明过于简略，不利于形成完整的软著材料链路。

## 5. 软著功能模块描述（可直接写入说明书）

### 5.1 软件名称建议
1. 蜜蜂虚拟飞行行为仿真与可视化系统
2. 基于 Unity 的蜜蜂飞行轨迹与采集行为模拟系统
3. 蜜蜂飞行姿态与目标趋近可视化仿真平台

### 5.2 软件简介
本软件是一套基于 Unity 引擎开发的蜜蜂虚拟飞行仿真与可视化系统，用于对蜜蜂在三维场景中的飞行轨迹、振翅扰动、目标趋近、悬停采集、障碍规避和姿态变化过程进行交互式展示。系统强调可视化模拟与行为演示，适合用于虚拟仿真展示、教学演示、科研方案表达和软著成果整理。

### 5.3 软件开发目的
1. 以较低复杂度实现具有可解释性的蜜蜂飞行行为模拟；
2. 将飞行控制、目标行为、轨迹显示、扰动参数、姿态变化组织为可独立描述的软件模块；
3. 为软件著作权申报、成果答辩和演示视频提供稳定的功能展示基础。

### 5.4 主要功能模块
1. **飞行控制模块**：支持手动控制与自动目标趋近飞行。
2. **振翅扰动模拟模块**：通过振荡参数与 Curl Noise 扰动模拟飞行微扰。
3. **目标趋近与采集模块**：支持目标搜索、趋近、悬停和采集行为。
4. **障碍规避模块**：对场景障碍物与地面进行规避控制。
5. **姿态变化模块**：根据转向、上升、下降和避障状态呈现侧倾与俯仰变化。
6. **飞行轨迹可视化模块**：实时记录并绘制飞行轨迹。
7. **演示交互模块**：提供相机跟随、可视化开关、暂停控制等演示能力。

### 5.5 技术特点
1. 基于 Unity 三维场景实现实时交互式仿真。
2. 通过参数化方式统一管理速度、扰动、避障、姿态和目标行为。
3. 采用轻量化设计，便于快速演示、截图和模块化说明。
4. 兼顾视觉真实性与实现复杂度，适合成果展示而非高精度实验仿真。

### 5.6 创新点 / 特色功能
1. 将**蜜蜂飞行轨迹可视化**与**行为控制逻辑**统一到同一演示场景中。
2. 将**振翅扰动模拟**与**姿态变化控制**结合，增强蜜蜂飞行的动态真实感。
3. 将**目标趋近、悬停与采集行为**组织为连续行为链路，便于说明业务闭环。
4. 通过**障碍规避 + 参数化控制 + 可视化开关**形成适合软著展示的交互型仿真系统。

### 5.7 操作流程（简写版）
1. 打开 `Demo.unity` 场景；
2. 运行场景并启动蜜蜂飞行模拟；
3. 通过键盘控制或自动模式观察蜜蜂飞行；
4. 查看轨迹、扰动、目标趋近、悬停采集、避障与姿态变化效果；
5. 使用可视化开关和暂停功能进行截图或录屏。

### 5.8 系统运行流程（可写入申报材料）
初始化场景与蜜蜂对象 → 读取飞行参数 → 执行飞行控制与扰动计算 → 执行目标检测与趋近/采集行为 → 执行障碍规避与姿态修正 → 输出轨迹和可视化结果 → 接收用户交互指令。

### 5.9 适合软著申请表使用的功能描述
本软件实现了蜜蜂虚拟飞行行为的三维可视化模拟，具备飞行控制、目标趋近、悬停采集、障碍规避、姿态变化、飞行轨迹绘制和参数化交互展示等功能，可用于蜜蜂飞行过程的虚拟仿真演示与成果展示。

## 6. 演示步骤（简洁版）

### 6.1 演示前准备
1. 打开 Unity 工程。
2. 打开 `Assets/Scenes/Demo.unity`。
3. 确认场景内对象存在：`Bee`、`Main Camera`、`Main`、`VisualizationManager`、`GameManger`。
4. 如需自动演示，在 Inspector 中将 Bee 对象上的 `BeeSimulation.controlMode` 切换为 `AutopilotTargets`。

### 6.2 演示过程
1. 点击 Play，展示蜜蜂初始化位置与跟随镜头。
2. **手动飞行演示**：
   - `W/S`：前进/减速
   - `A/D`：转向
   - `F`：上升（场景里 `ascendKey` 已配置为 102，即 F）
   - `LeftCtrl`：下降
   - `LeftShift`：加速
3. 观察蜜蜂在飞行过程中的**姿态变化**（转弯侧倾、升降俯仰）。
4. 点击“可视化”按钮，展示或关闭**调试射线、受力和轨迹**。
5. 切换到自动模式后，展示蜜蜂对 3 个目标点的**趋近、悬停和采集行为**。
6. 展示蜜蜂对树木/灌木等 `Obstacle` 对象的**规避过程**。
7. 按 `Space` 触发暂停，便于截图和参数展示。

### 6.3 建议的答辩/录屏顺序
1. 先展示总场景与蜜蜂模型；
2. 再展示手动飞行与姿态变化；
3. 再展示轨迹与扰动；
4. 再展示自动趋近与采集；
5. 最后展示可视化开关、参数面板和暂停截图。

## 10. 当前项目可能存在的问题与最小修改建议

### 10.1 可能存在的问题
1. 缺少统一 HUD，评审无法快速理解速度、高度、模式、采集状态。
2. 演示过程依赖 Inspector 修改模式，不够流畅。
